# Security Policy

## Reporting a vulnerability

If you find a security issue in FIMI Radar (the code in this repository or the deployment
at `fimi.viajeinteligencia.com`), please report it **privately**:

- Email: **info-fimi@viajeinteligencia.com**
- Please do **not** open a public issue for security problems.

We aim to acknowledge reports within **72 hours** and to provide a fix or mitigation as soon
as reasonably possible. We will credit reporters who wish to be acknowledged.

## Scope

- The server-side code in this repository (`detection/`, `collectors/`, `normalizer/`,
  `features/`, `clustering/`, `attribution/`).
- The public API (`/api/*`) and the static dashboard generated by `detection/gen_fimi_html.py`.

Out of scope: third-party dependencies (report those upstream; we track them with
Dependabot) and social platforms we only read from.

## What we already do

- **Least data:** only public data is processed; no private accounts, no personal profiling.
- **Secrets:** credentials live only in `.env` (gitignored, `chmod 600`); never in the repo.
- **Access control:** admin endpoints require an `x-admin-secret` header; the database and
  `.env` are owner-only (`600`).
- **Transport & headers:** HSTS, CSP, `X-Frame-Options: DENY`, `X-Content-Type-Options:
  nosniff`, `Referrer-Policy`.
- **Rate limiting:** nginx `limit_req` on `/api/*`.
- **Input validation:** strict validation of cluster identifiers and request parameters;
  errors are always returned as JSON (never a stack trace).
- **Automated scanning:** OpenSSF Scorecard, Bandit and Dependabot run via GitHub Actions.

## Disclosure

We follow coordinated disclosure: we will work with you on a timeline and publish a fix
before any public detail, unless there is a compelling reason otherwise.
